# M1.5 — 憑據輪換清單

> **本文件僅列出憑據類型、用途與輪換方法。不包含、不顯示任何實際 Secret 值。
> 輪換由用戶手動執行，本階段不撤銷、不更改任何憑據。**

## 輪換背景

對話與本地文件過程中，部分憑據曾以明文形式出現在終端命令與日誌中（沙箱環境，但按
最低權限原則仍建議輪換）。優先級按暴露程度排列。

## 清單

| # | 憑據 | 用途 / 使用位置 | 暴露風險 | 建議 | 輪換方法 |
|---|---|---|---|---|---|
| 1 | **GitHub PAT**（classic，repo+workflow scope） | 本機 git push 憑據；曾出現在終端命令中 | 中：曾明文輸入 | ★ 建議輪換 | GitHub → Settings → Developer settings → Personal access tokens → 刪除舊 token → Generate new（最小 scope：repo+workflow，設過期日）→ 本機 `git credential reject` 後重新登入 |
| 2 | **Cloudflare Pages Token** | 本機 `npx wrangler pages deploy` 環境變數 | 中：曾明文輸入 | ★ 建議輪換 | CF Dashboard → My Profile → API Tokens → Roll（一鍵換值，權限不變）→ 更新本機部署腳本變數 |
| 3 | **Cloudflare D1/Workers Token** | 本機 `wrangler deploy` / `d1 execute` / d1 export | 高：M1 期間在多條命令中反覆明文使用，且具 D1 寫權限 | ★★ **優先輪換** | CF → API Tokens → 建新 token（權限：D1 Edit + Workers Scripts Edit，帳戶資源限定本帳戶）→ 驗證新 token 可部署 → 刪除舊 token |
| 4 | **Resend API Key** | Worker secret `RESEND_API_KEY`；曾明文輸入 | 中 | ★ 建議輪換 | Resend → API Keys → Create（Full access 或僅 sending）→ `npx wrangler secret put RESEND_API_KEY`（在 amcm-worker 目錄）→ 刪除舊 Key |
| 5 | **DeepSeek API Key** | 本機 ETL（`amcm-etl/secrets.env`，未入 Git）；瀏覽器 BYOK 由用戶自填 | 低：僅存在於本機 secrets.env 與對話 | 可暫緩 | DeepSeek 平台 → API Keys → 刪除舊 → 新建 → 更新 secrets.env |
| 6 | **Worker secret `ADMIN_TOKEN`** | `/api/cron/run?token=` 手動觸發口 | 中：URL 參數可能進入訪問日誌 | ★ 建議輪換 | 生成新隨機串 → `npx wrangler secret put ADMIN_TOKEN` → 用新值實測一次 cron/run |
| 7 | **APK 簽名 keystore**（`android/keystore/release.keystore` 及 amcm 同款，密碼 android） | APK 簽名；密碼極弱且已在文件中出現 | 低（僅本地分發，不上架） | 可暫緩；**若未來上架 Google Play 必須重建強密碼 keystore** | keytool -genkeypair 重建 → 所有 APK 需重新簽名 → 舊包無法覆蓋安裝（需卸載重裝） |

## 執行順序建議

1. 先輪 #3（D1/Workers，寫權限最大）→ 2. #2 Pages → 3. #1 GitHub → 4. #4 Resend → 5. #6 ADMIN_TOKEN → 6. 其餘按需。

## 通用注意

- 輪換後所有受影響的自動化（部署腳本、Worker secret）需同步更新並做一次**驗證性部署/調用**再刪舊值，避免服務中斷。
- 新憑據請勿再貼入對話；本機可存於 `amcm-etl/secrets.env`（已確認不入 Git）或系統憑據管理器。
