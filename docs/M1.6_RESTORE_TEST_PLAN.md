## 四、級別 B 完整流程（未獲批准不執行）

1. **建副本庫**：`npx wrangler d1 create amcm-db-restore-test`（僅建副本，不觸生產）。
2. **建表**：執行 `amcm-etl/d1_schema.sql`（與生產同構，含 FTS 觸發器）。
3. **逐表導入**：`wrangler d1 execute amcm-db-restore-test --remote --file=backups/d1-amcm-20261105-preM2-<t>.sql`（5 表）。
4. **重建 FTS**：`INSERT INTO chunks_fts(chunks_fts) VALUES('rebuild');`
5. **驗收斷言（全部通過才算成功）**：
   - `SELECT COUNT(*) FROM guidelines` = **170**；`chunks` = **3,617**；`news` = 20；`email_subscribers` = 2；`sync_state` = 1；
   - **id14** = `002/2013-AMCM`，`SUPERSEDED`，`superseded_by='026/2025-AMCM'`；
   - **id15** = `026/2025-AMCM`，`IN_FORCE`，`superseded_by IS NULL`；
   - **自我取代數量 = 0**（`SELECT COUNT(*) FROM guidelines WHERE superseded_by IS NOT NULL AND superseded_by=doc_number`）；
   - **FTS 重建成功**：`SELECT COUNT(*) FROM chunks_fts` > 0 且等於可索引行數；
   - **中文搜索命中**：副本庫執行與生產 search 同款 FTS 查詢（如「雲端」）有結果且 (guideline_id, page_number) 定位正確；
   - **英文搜索命中**：`liquidity` 有結果。
6. **清理**：全部斷言通過後 `wrangler d1 delete amcm-db-restore-test`（僅刪副本庫）。
7. **失敗處置**：任何斷言不過 → 記錄差異 → 不得動生產 → 排查導出/導入環節後重演。

## 五、注意事項

- 演練全程不綁定 Worker（不部署指向副本庫的 Worker），避免任何生產誤寫。
- 副本庫導入前先確認 `d1_schema.sql` 與生產表結構一致（列序差異由帶列名 INSERT 天然免疫）。
- 級別 B 需要的批准：建立/刪除副本數據庫（嚴格限制 #2 所指事項），故本階段僅完成級別 A。
