## 二、建議方案：作為子目錄納入 richapps 倉庫

推薦 `worker/amcm-api/`（與 `android/`、`android-afcm/`、`amcm/` 平級），理由：單一倉庫管理、Issue/PR 統一、備份文件可選擇性豁免。備選（獨立倉庫）暫不需要。

### .gitignore（新建於 `worker/amcm-api/` 或沿用根倉庫規則）

```gitignore
.wrangler/
backups/
*.sql
*.json.bak
.dev.vars
.env
```

- `backups/` 含 D1 全量導出與 M1 中間態快照——**不入庫**（體積 7.6MB+，且屬資料類）；其保留本機原位，另建議異地副本（見 M1.5 報告缺口 #2）。
- `amcm-etl/`（含 secrets.env、amcm.db）**不在本方案範圍**，保持倉庫外。

### 執行步驟（待批准後）

1. `mkdir -p worker/amcm-api && cp -r amcm-worker/src amcm-worker/wrangler.toml worker/amcm-api/`（**複製而非移動**，原目錄保留至新流程驗證成功）；
2. 新建 `worker/amcm-api/.gitignore`（如上）；
3. 根 `.gitignore` 增補 `worker/amcm-api/.wrangler/`；
4. `git add worker/amcm-api && git commit -m "納入 amcm-api Worker 源碼（快照=生產 2026-11-05T07:54Z 部署）" && git push`；
5. 在 `worker/amcm-api/` 目錄執行一次只讀驗證：`npx wrangler deployments list`（確認該目錄下 wrangler.toml 解析正常、與生產一致）；
6. **後續 M2 起所有 Worker 改動在新目錄進行並經 Git 提交**；舊 `amcm-worker/` 降級為備份與快照存檔（backups/ 原地保留），觀察一個里程碑後歸檔。

### 版本對應記錄

- 生產 Worker Version：部署時間 `2026-11-05T07:54:00.600Z`（wrangler deployments list 不回顯短 ID；M1 報告記載 Version ID `3963eed4`）。
- 源碼快照：`src/index.js` 480 行，SHA256 建議入庫時記錄於本文件附錄（批准執行時計算）。

## 三、風險與回滾

- 風險極低：純複製+新增，不改動原目錄與部署。
- 回滾：刪除 `worker/amcm-api/` 目錄並 revert 提交即可，生產不受影響。
