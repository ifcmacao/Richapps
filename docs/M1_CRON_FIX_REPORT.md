## 1. 修復內容

### 1.1 upsert 匹配鍵（最終版）
- 精確鍵：`sector + normTitle + normDoc(doc_number)`（有文號行）
- 無文號行鍵：`sector + normTitle + NODOC`
- **二級回落**：官方行無文號且精確鍵不匹配時，按 `sector + normTitle` 回落合併；
  **官方行帶文號但精確鍵不匹配 → 一律視為新文件插入，嚴禁合併進舊條目**（防止把新指引併入同名舊文件改寫其身份）。
- normT：去空白、全半形統一、大寫、**剝離標題內嵌文號後綴「（第 X/Y-Z 號）」**（官方 API 標題自帶文號後綴而 ETL 存純標題，是首次匹配失敗的根因）。
- 更新分支：**永不改動 doc_number / doc_year / status**（版本身份不可變）；回落合併（官方無文號→原有文號）時跳過 summary 覆寫（原行 summary 含文號身份信息）。
- 寫入方式：`env.DB.batch()` **原子批量**——全部成功或全部回滾，杜絕半途失敗留下部分寫入（此缺陷曾在回歸中實際發生，見 §2）。

### 1.2 效力鏈推導（最終版）
- 僅同 sector+normTitle 分組且**文號不同、年份嚴格不同**時推導；
- 最新年份=IN_FORCE，更舊年份=SUPERSEDED→指向最新文號；
- 同 doc_number 不互指（杜絕自我取代）；年份缺失/相等不推導；無文號不參與。
